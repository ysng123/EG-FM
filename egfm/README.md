# Energy-Guided Flow Matching

`egfm` is the small, backbone-independent PyTorch library for the Energy-Guided Flow Matching (EG-FM) path. It turns a clean image into a sample-adaptive moving endpoint that releases spectral information from coarse to fine, and provides the exact target used to train a flow-matching model.

The package contains no model architecture, dataset, training engine, sampler, or checkpoint code. It can therefore be used from PixelDiT, JiT, or another PyTorch denoiser without importing a full research repository.

## Installation

Python 3.10 and PyTorch 2.8 are required.

```bash
pip install .
```

For an editable development installation with tests:

```bash
pip install -e ".[test]"
pytest
```

The distribution is named `energy-guided-flow-matching`; the Python import is `egfm`.

## Training usage

```python
import torch

from egfm import EnergyGuidedPath, make_training_batch

path = EnergyGuidedPath(
    sigma0=3.5,
    curve="smootherstep",
    release_start=0.0,
    release_end=1.0,
)

# images: finite floating tensor [batch, channels, height, width]
t = torch.rand(images.shape[0], device=images.device, dtype=images.dtype)
flow = make_training_batch(images, t, path)

v_prediction = model(flow.state, flow.time, labels)
loss = (v_prediction - flow.velocity).square().mean()
```

The constructed path is

```text
state(t)    = t * endpoint(t) + (1 - t) * noise
velocity(t) = endpoint(t) + t * endpoint_velocity(t) - noise
```

`EnergyFlowBatch` exposes `time`, `state`, `velocity`, `endpoint`, `endpoint_velocity`, and the sampled or supplied `noise`.

Pass an explicit noise tensor for deterministic construction:

```python
noise = torch.randn_like(images)
flow = make_training_batch(images, t, path, noise=noise)
```

`noise` must match the image shape, dtype, and device. `noise_scale` affects only noise generated by `make_training_batch`; it does not rescale explicitly supplied noise.

## x-prediction

An x-prediction model (`target="x"`) can be converted to the corresponding velocity field:

```python
from egfm import prediction_to_velocity

x_prediction = model(state, t, labels)
velocity = prediction_to_velocity(
    x_prediction,
    state,
    t,
    path,
    target="x",
)
```

For a velocity-prediction model, use `target="velocity"`; the prediction is returned unchanged and the energy-guided endpoint does not need to be evaluated during sampling.

## Release schedules

The built-in schedules are `linear`, `cosine`, `smoothstep`, and `smootherstep`. List or evaluate them with:

```python
from egfm import evaluate_release_schedule, list_release_schedules

print(list_release_schedules())
release, derivative = evaluate_release_schedule(t, "smootherstep")
```

A custom schedule returns its value and derivative. Both results must match the input shape, dtype, and device:

```python
import torch

from egfm import EnergyGuidedPath, register_release_schedule


def quadratic(u: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
    return u.square(), 2.0 * u


register_release_schedule("quadratic", quadratic)
path = EnergyGuidedPath(curve="quadratic")
```

Schedules receive time clamped to `[0, 1]`; their derivative is set to zero at and outside the interval boundaries.

## Input contract

- Image-like inputs are finite floating tensors in BCHW layout, with no empty dimensions.
- Time is a finite floating vector with shape `[batch]`. Public helpers move it to the reference image's device and dtype. `EnergyGuidedPath` uses float32 internally for the FFT and path computation and converts outputs back to the image dtype.
- A custom endpoint path returns `(endpoint, endpoint_velocity)`, both matching the input image's shape, dtype, and device.
- `sigma0`, release bounds, `noise_scale`, and `eps` must be finite and in their documented domains.

Time values outside `[0, 1]` are accepted by the path: the release schedule is clamped and its derivative is zero outside the active interval.
